## Commands

```bash
# Development (start backend on :5000, frontend dev server on :5173 with /api proxy)
npm run dev:backend        # Express server with tsx watch
npm run dev:frontend       # Vite dev server

# Production build
npm run build              # vite build + esbuild server/index.ts → dist/server.mjs
npm run start              # node dist/server.mjs

# Type checking (no emit)
npm run typecheck

# Tests
npm run test:e2e           # Playwright end-to-end
npm run test:unit          # Unit tests via tsx
npm run test:integration   # Paystack integration test only

# DB migrations (Drizzle Kit)
npx drizzle-kit generate   # Generate migration SQL from schema changes
npx drizzle-kit migrate    # Apply pending migrations to DB

# Platform audit
npm run audit:platform
```

## Architecture

This is a **multi-vendor e-commerce + last-mile delivery platform** (KiyuMart). Currency: GHS only.

### Stack
- **Frontend:** React 18 + TypeScript, Vite, Wouter (routing), TanStack Query, Zustand, Radix UI / shadcn, Tailwind CSS, Framer Motion, Socket.IO client
- **Backend:** Express 4 + TypeScript (ESM), Socket.IO, Drizzle ORM, Neon PostgreSQL
- **Payments:** Paystack — **inline popup is primary** (never redirect as default flow)
- **Media:** Cloudinary uploads
- **Email:** Nodemailer
- **Real-time:** Socket.IO (users join personal room by their `id` for targeted events)
- **PWA:** vite-plugin-pwa with workbox caching

### User roles
Seven roles: `super_admin`, `admin`, `seller`, `buyer`, `rider`, `pickup_agent`, `agent`. The `super_admin` bypasses all role-feature gates. Per-user capability overrides live in the `roleFeatures` JSONB column.

### Auth
JWT stored in cookie or `Authorization` header. `requireAuth` → `requireRole` → `requirePermission` middleware chain in `server/auth.ts`. Tokens expire in 7 days, signed with `SESSION_SECRET`.

### Database
Drizzle ORM against Neon serverless PostgreSQL. Schema lives entirely in `shared/schema.ts`. All query logic lives in `server/storage.ts` — never write Drizzle queries directly in routes. DB connection auto-selects Neon WebSocket driver vs standard `pg` pool based on `DATABASE_URL`/`DB_DRIVER` env.

### Order state machine
Canonical flow: `pending → processing → packaged → ready → [mode-dependent] → completed`

Two modes controlled by `platform_settings.isExternalRiderSystemEnabled`:
- **Internal rider mode** (`false`): adds `searching_rider → assigned → rider_arrived → picked_up → in_transit → en_route → delivered`
- **External delivery mode** (`true`): adds `external_dispatch_arranged`; rider matching is skipped

State transitions live in `server/services/orderStateMachine.ts`.

### Rider mode UI gating
Every page that shows rider-specific UI **must** gate it behind `isExternalRiderSystemEnabled === false`. The frontend pattern is:

```tsx
const { platformSettings } = usePlatformSettings();
const showInternalRiderFeatures = !platformSettings?.isExternalRiderSystemEnabled;
```

Route-level guards in `App.tsx`: `withExternalRiderRouteGuard` (hides rider routes), `withAdminExternalRiderFeatureGuard` (hides admin rider management).

### Payments
- **Primary flow:** Paystack inline popup (`@paystack/inline-js`). Never use `authorization_url` redirect as the default path.
- **Webhook:** `/api/webhooks/paystack` (single endpoint). Idempotency guard returns 200 immediately if `idemp.used === true && idemp.usedAt` is set.
- Multi-vendor checkout uses `getOrdersByCheckoutSession()` (not a full table scan).

### Background workers (server/workers/)
Four workers start at server boot:
1. **Payout processor** — transfers commissions to seller/rider wallets
2. **Promotional expiry** — marks expired promotions inactive
3. **Order auto-cancel** — cancels unpaid orders after timeout
4. **Notification reminder** — sends payment reminders

### Social Commerce ("Magic Link") system
- Each product has a `slug` column (`shared/schema.ts`). Slug is auto-generated on product creation in `server/routes.ts` via `generateProductSlug()`. For older products with no slug, sellers can generate one on-demand via `POST /api/products/:id/generate-slug` — a "Generate Link" button in the share dialog.
- Route `/p/:slug` → `client/src/pages/SocialProductPage.tsx` — minimalist page with no global header/footer, inline Paystack pay button, modifier selector. Optimised for Instagram "link in bio."
- Backend endpoint: `GET /api/p/:slug` returns product + store + modifiers. Checkout: `POST /api/orders/social-checkout` (uses `deliveryMethod: "rider"`).
- **Cart Links:** sellers generate multi-item pre-filled cart URLs via `POST /api/seller/cart-links`. Public checkout at `/cart/:token` (`client/src/pages/CartLinkCheckout.tsx`). Backend: `GET /api/cart-links/:token`, `POST /api/orders/cart-checkout`. Cart links expire after 48h. `cart_links` table in `shared/schema.ts`. Commissions and processing fees apply.
- **No seller→buyer WhatsApp direct chat.** The `whatsappNumber` field was removed from seller settings and product share dialogs to keep transactions on-platform.

### Platform branding & PWA icon system
- `platformSettings` has `logoLight`, `logoDark`, `favicon` columns (added to `shared/schema.ts` and to `server/index.ts` self-heal migrations).
- `GET /api/public/platform-settings` exposes these to all users without auth.
- `usePlatformSettings` hook in `client/src/hooks/usePlatformSettings.ts` provides `logo`, `logoLight`, `logoDark`, `favicon`, `primaryColor`.
- `Logo.tsx` uses `usePlatformSettings()` to override bundled assets.
- `FaviconInjector` component in `App.tsx` updates all `<link rel="icon">` and `<link rel="apple-touch-icon">` tags when `favicon` changes.
- `GET /api/public/app-manifest` serves a dynamic `manifest.json` with DB-stored icon and color. `client/index.html` points to this endpoint (not a static file).

### Bolt Food experience (restaurants & local vendors)
A dedicated mobile food ordering surface lives alongside the e-commerce flows.
Active when a store has `businessType` of `local_vendor` / `restaurant`, OR
`storeType` of `food_beverages` / `restaurant`, OR `merchantCategory === QUICK_EATS`
(`isFoodVendorStore` in `client/src/lib/foodVendors.ts` is the single source of truth).

- **Discovery:** `client/src/pages/mobile/MobileAllVendors.tsx` at `/mobile/vendors` (also `/vendors` on mobile). Sticky DELIVER TO header, debounced search, sub-tab pills, cuisine chips from food-scoped categories, super-admin banner, top picks rail, vertical store cards.
- **Restaurant detail:** `client/src/pages/mobile/MobileFoodStorePage.tsx` — lazy-rendered by `SellerStorePage.tsx` when `isMobile && isFoodVendorStore(store)`. Sticky scroll-spy category tabs + Bolt-style menu rows.
- **Food item detail:** `client/src/pages/mobile/MobileFoodDetail.tsx` — routed via `MobileProductDecider` in `App.tsx`. Modifier groups from `product_modifiers`, sticky live-priced Add to cart CTA.
- **Order tracking:** `client/src/pages/mobile/MobileFoodOrderTracking.tsx` — `OrderTracking.tsx` branches to it for mobile single-order views when the store is food. Vertical timeline + rider card + payment summary.
- **Live quote API:** `GET /api/stores/quotes?ids=&lat=&lon=&city=&region=` returns per-store `prepMins / etaLowMins / etaHighMins / deliveryFee (from delivery_zones) / minOrderAmount / distanceKm / totalSold`. Use this rather than hardcoding.
- **Schema additions:** `stores.prepTimeMins`, `stores.minOrderAmount`, `hero_banners.placement` + `theme_color`, `categories.productFieldsConfig`, `platform_settings.enable_3d_ar`.
- **Separation invariants:** Homepage banners (`placement=home`) never appear on the food page; food banners (`placement=food_vendors`) never appear on the homepage. Food-scoped categories never appear in the generic Shop by Category surface. 3D/AR is hard-disabled for food vendors regardless of `platform_settings.enable_3d_ar`.
- **Admin surfaces:** AdminHeroBanners has Homepage / Restaurants & Local Vendors tabs. AdminCategoryManager has Stores / Restaurants & Local Vendors / Pending tabs with a "Seed default cuisines" button and a per-cuisine field builder. `/admin/food-products` (`AdminFoodProducts.tsx`) lists food items only; `/admin/products` excludes them and links to the food page.
- **Variant section** in `SellerProducts.tsx` is hidden for `food_beverages` AND `restaurant` storeTypes — sellers use `product_modifiers` instead.

### Merchant categories & store personas
Stores have a `merchantCategory` text column (values: `QUICK_EATS`, `HEALTH_ESSENTIALS`, `RETAIL_BOUTIQUE`, `GENERAL_PROVISIONS`). This is separate from `storeType` in `shared/storeTypes.ts` (which drives adaptive product fields).

- `shared/storeTypes.ts` → `STORE_TYPE_PRODUCT_CONFIG` maps each `storeType` to a set of dynamic product fields rendered in `SellerProducts.tsx` via `DynamicFieldRenderer`.
- `food_beverages` has a `prepTime` (Preparation Time) field.
- `health_wellness` has `barcode` (Barcode/UPC) and `prescriptionRequired` fields.
- Merchants set `merchantCategory` in `SellerSettings.tsx`; admins/super-admins can also set it per-store in `StoreDetailsPage.tsx`.

### Product modifiers
`product_modifiers` table (`shared/schema.ts:446`) stores food add-ons for `QUICK_EATS` stores. API routes: `GET/POST /api/products/:id/modifiers`, `PATCH/DELETE /api/products/:id/modifiers/:modId`. Modifiers are rendered in `SocialProductPage` and `ProductDetails`.

### Store white-labeling / branding
Stores have a `brandingConfig` JSONB column (`primaryColor`, `accentColor`, `logoOverride`, `coverImage`, `tagline`). Applied:
- **SocialProductPage** — brand color on Pay Now button + price display.
- **SellerStorePage** (buyer-facing `/sellers/:id`) — CSS variables `--store-brand-primary` / `--store-brand-accent` injected into `document.documentElement`, brand color applied to banner fallback and avatar, tagline displayed.
- **SellerSettings branding card** — live preview panel (cover banner, avatar with primary color, sample product card) + native `<input type="color">` pickers synced with hex text inputs for primary and accent colors.
- **Admin/super-admin** can edit branding per store in `StoreDetailsPage.tsx`.

### Seller support chat (SellerMessages.tsx)
- Sellers chat with the KiyuMart support team (admins + agents) via `/seller/messages`.
- When a seller sends a message, the backend creates **one DB record per support staff member** (broadcast pattern) so all agents see the conversation. The `GET /api/messages/:userId` unified-thread query deduplicates by filtering the seller's outgoing messages to only those where `receiverId = req.params.userId` — prevents N duplicate messages in the seller's view.
- `MessageStatusTicks` must receive `variant="primary"` when rendered inside the green sender bubble so ticks use `text-white/60` (sent/delivered) and `text-sky-200` (read) instead of the default dark grey which is invisible on green.

### Rider searching animation
When `searching_rider` status is active in internal rider mode (`!isExternalRiderSystemEnabled`), both `SellerOrders.tsx` and `OrderTracking.tsx` show a pulsing "Searching for Logistics Partner" / "Finding Your Rider" animation card instead of raw status text.

### Rider identity visibility rule
Sellers see rider name/phone/vehicle **only** when `showInternalRiderFeatures === true` AND order status is `assigned` or later. The rule is enforced in `SellerOrders.tsx`. Buyer-facing tracking does not expose rider PII.

### Delivery zone fee suggestions
`AdminDeliveryZones.tsx` shows merchant-type fee quick-fill presets (via `MERCHANT_TYPE_FEE_PRESETS` constant) in the zone creation dialog. Admins click a preset to auto-fill the fee field based on the intended merchant type (Quick Eats / Health Essentials / Retail Boutique / General Provisions).
